# Skills Marketplace Design

**Date:** 2026-06-12
**Status:** Approved
**Repo:** github.com/alkimake/skills

## Goal

Turn this personal skills collection into a marketplace that any supported agent can install skills from — Claude Code natively, plus Codex CLI, Gemini CLI, GitHub Copilot CLI, Cursor, and any other agent supporting the Agent Skills spec (agentskills.io) — with both whole-collection and per-skill installation.

## Decisions

| Decision | Choice |
|---|---|
| Target agents | Cross-agent from day one (Claude Code + all Agent Skills spec adopters) |
| Install granularity | Both: an all-skills bundle and individually installable skills |
| Manifest maintenance | Generated by script, CI-validated drift check |
| Structure | Single repo, skills moved under `skills/`, dual manifests (approach A) |

## Background (verified 2026-06-12)

- The Agent Skills spec (`SKILL.md` with `name` + `description` frontmatter, optional `scripts/`, `references/`, `assets/`) is adopted by 32+ agents.
- `npx skills add owner/repo` (vercel-labs/skills) installs from a GitHub repo into 70+ agents; supports `--skill <name>` for individual skills and `-a <agent>` targeting. It expects skills under a `skills/` directory.
- Claude Code marketplaces: a `.claude-plugin/marketplace.json` in the repo enables `/plugin marketplace add alkimake/skills` and `/plugin install <plugin>@<marketplace>`.
- Gemini CLI installs directly from a git URL: `gemini skills install <url>`.
- The current repo keeps skills at the root, which is the non-canonical fallback path for installers — hence the restructure.

## Repo layout (target)

```
skills/                              # all skills move here (git mv)
  release/SKILL.md
  glab-workflow/SKILL.md
  subagent-driven-development/SKILL.md
.claude-plugin/
  marketplace.json                   # generated — Claude Code marketplace manifest
scripts/
  generate-manifests.mjs             # scans skills/*/SKILL.md → regenerates manifests + README table
.github/workflows/validate.yml       # CI: frontmatter validation + manifest drift check
README.md                            # generated skill table between markers + per-agent install docs
CLAUDE.md                            # updated to reflect new structure
```

- `glab-workflow-workspace/` (untracked scratch dir) gets added to `.gitignore`.
- `.memsearch/` stays untouched.
- Skill directories keep their supporting files (e.g. `subagent-driven-development/TEST.md`) alongside `SKILL.md`.

## Manifests

`.claude-plugin/marketplace.json` is generated, never hand-edited. It contains:

- **Marketplace identity:** name `ake-skills`, owner Alkim Ake Gozen.
- **One plugin per skill** — `release`, `glab-workflow`, `subagent-driven-development` — each with `source: "./skills/<name>"` (the skill directory is the plugin root) and `skills: ["./"]`, plus the description pulled from that skill's frontmatter.
- **One bundle plugin** — `ake-skills` — with `source: "./"` and **no `skills` array**: Claude Code auto-discovers skills under `<plugin-root>/skills/`, so an explicit array would duplicate every skill. New skills join the bundle automatically on regeneration (the generator never emits a `skills` key on the bundle).

**Versioning:** plugin `version` fields are stamped from the `VERSION` file at the repo root (single version source — git tags lag the release commit, which would break the CI drift check). The existing `/release` skill is the version authority; its flow becomes bump VERSION → regenerate → commit → tag.

## Install story (user-facing, documented in README)

| Agent | Command |
|---|---|
| Claude Code (native) | `/plugin marketplace add alkimake/skills`, then `/plugin install release@ake-skills` or `/plugin install ake-skills@ake-skills` for everything |
| Any agent via cross-agent CLI | `npx skills add alkimake/skills` (interactive picker), `--skill release` for one skill, `-a codex`/`-a cursor` etc. to target agents |
| Gemini CLI | `gemini skills install https://github.com/alkimake/skills` |
| Codex / Copilot / Cursor (manual) | copy `skills/<name>` into `~/.agents/skills/` (or agent-native path) |

No extra per-agent artifacts are required: the `skills/` layout plus spec-compliant frontmatter covers all supported agents. The local symlink workflow (`~/.claude/skills/<name>` → repo) keeps working, with symlinks pointing one level deeper.

## Generator and CI

`scripts/generate-manifests.mjs` — Node, zero dependencies (frontmatter fields are simple enough to parse without a YAML library):

1. Scan `skills/*/SKILL.md`, parse frontmatter.
2. Validate per the Agent Skills spec, failing loudly with file + reason:
   - `name` matches the directory name
   - `name` is 1–64 chars, lowercase alphanumeric + hyphens, no leading/trailing/consecutive hyphens
   - `description` present, 1–1024 chars
3. Read the `VERSION` file for the version stamp.
4. Emit `.claude-plugin/marketplace.json` (deterministic output: sorted skill order, fixed key order).
5. Rewrite the README skill table between `<!-- skills:start -->` / `<!-- skills:end -->` markers.

`.github/workflows/validate.yml` — on push/PR: checkout, run the tests and the generator, then fail on any staged diff. Any drift between skill directories and generated artifacts fails the build.

Adding a skill remains: `mkdir skills/<name>` + write `SKILL.md` + run the generator.

## Error handling

- Generator exits non-zero on any invalid frontmatter, missing SKILL.md in a skill directory, or unparseable frontmatter block, printing the offending file and reason.
- Missing `VERSION` file: version falls back to `0.0.0` with a warning (pre-first-release state).

## Testing / verification

1. Run the generator against the real repo; inspect `marketplace.json` output shape.
2. `npx skills add ./ --list` — confirm the cross-agent CLI discovers all three skills from the local checkout.
3. `/plugin marketplace add` from the local path — confirm Claude Code parses the manifest and lists bundle + per-skill plugins.
4. CI run on push validates the same on every future change.

## Out of scope

- Publishing/promotion (skills.sh leaderboard listing, etc.)
- A separate marketplace repo aggregating third-party skill repos (approach B — revisit if the collection grows beyond personal use)
- Auto-syncing copies into `.agents/skills/` or `.github/skills/` inside this repo (installers handle placement)
